# 酒疫主题器

作者：jiuyi
当前版本：0.13.0
最低 SillyTavern 版本：1.14.0

## 功能

- 从受信任的 GitHub、GitHub Pages 或 jsDelivr HTTPS 地址读取主题目录。
- 明确分开“☀ 日间主题”和“☾ 夜间主题”，不再用随机色卡或假窗口冒充主题预览。
- 主题卡优先显示依据该主题真实色调、代表物和视觉语言生成的身份 Logo；有真实截图时可作为次级回退。
- 每张主题卡提供“快速预览”：弹出后优先查看真实主题截图，支持上一项、下一项、左右滑动和键盘方向键；预览不会下载、保存或切换主题。没有真实截图时明确显示主题 Logo，不生成假界面图。
- 提供完全留在酒馆内的玩家反馈区：可搜索并选择主题、反馈类型，填写希望增加的模式、功能或修正内容；点击后由安全中继写入项目 GitHub Issue，不打开外部页面。
- 提供默认折叠的“CSS快捷修改提醒”：按全局字体、聊天正文、主题配色、消息卡片、输入区、按钮状态和手机正文分类，显示影响与风险并支持一键复制；代码不会自动应用到当前主题。
- 可以选择本地 JSON 美化文件并先收藏到主题器；选择文件不会加入酒馆、不会启用，也不会改变当前主题。收藏后仍需玩家再次点击“加入酒馆主题列表（不启用）”。
- 每次测试版本都保留在 GitHub；已安装的纯测试主题会持续显示，其他未批准版本默认收进关闭的“其他版本”或“其他测试主题”，不会冒充正式推荐。
- 发现会阻断操作的坏主题时可以在维护目录中标记 `withdrawn`；它会从玩家目录完全移除，但固定提交历史继续保留，修复并重新批准后才能恢复。
- 主题按日间与黑夜分组，版本显示可读名称、正式/测试状态、推荐标记和简短更新记录。
- GitHub Raw 下载较慢时自动重试，并尝试 jsDelivr 备用地址。
- 下载后检查主题JSON格式与主题名称；目录中的旧SHA-256字段不再参与安装判断，也不会因哈希不一致停止拉取。
- 点击一次即可安装或更新主题、自动刷新并切换。
- 玩家可以在订阅器设置中自行开启“魔棒返回保护”；开启后，魔棒菜单会增加一个小十字星 `✦ 返回上个主题` 入口，不再默认显示页面悬浮按钮。
- 使用魔棒入口返回后，订阅器会记录刚才的坏主题；回到设置面板可点击“删除刚才的坏主题”，通过酒馆原生接口删除本地文件。
- 电脑端在保护开启时还可以按 `Ctrl+Alt+Shift+R` 强制返回；快捷键不依赖魔棒菜单是否能展开。
- 主题包含的远程图片、字体和 `@import` 会随主题加载，并在控制台留下资源提示。
- 通过 SillyTavern 原生 `/api/themes/save` 接口保存主题。
- 不会后台静默覆盖主题，也不会读取聊天、密钥或私人设置。

## 本地安装

### 推荐：使用 SillyTavern 扩展安装器

打开 SillyTavern 的“扩展”页面，在“安装扩展”中粘贴：

```text
https://github.com/jiuyi777/sillytavern-theme-subscriber
```

安装后刷新 SillyTavern。通过仓库地址安装的版本可以使用 SillyTavern 原生扩展更新功能。

### 酒馆内反馈中继

扩展固定请求 `https://jiuyi-theme-feedback.netlify.app/api/feedback`。中继源码位于 `netlify/functions/feedback.ts`，只接受主题、反馈类型、玩家主动填写的内容和可选设备信息，再由服务端创建本仓库 Issue。

部署时在 Netlify 服务端设置 `GITHUB_ISSUES_TOKEN`；令牌只需对本仓库拥有 Issues 写权限，严禁写入扩展 JavaScript、目录 JSON或提交历史。中继未部署或未配置时，酒馆内表单会保留输入并显示失败，不会回退为外部跳转。

### 手动安装

将整个目录放入：

```text
SillyTavern/data/default-user/extensions/theme-subscriber/
```

然后重启或刷新 SillyTavern。在“扩展”设置中打开“酒疫主题器”。

## 使用

1. 填写远程 `catalog.json` 地址。
2. 点击“检查更新”。
3. 默认直接使用用户批准的推荐正式版；如需测试版或旧版，展开“其他版本”或“测试主题”。
4. 点击“安装并切换”“安装此版本并切换”或“切换”。
5. 新安装或更换版本时酒馆会自动刷新并启用目标主题，无需手动导入文件。
6. 需要常用CSS时展开“CSS快捷修改提醒”，再展开具体项目并点击“复制代码”；复制后先替换示例颜色、字体并确认真实节点。
7. 需要收纳电脑或手机中的美化文件时，展开“导入本地美化文件”并选择 JSON；确认无误后再主动加入酒馆主题列表。
8. 需要连续比较主题时，点击卡片图片右下角的眼睛按钮；关闭预览后仍停留在原主题列表位置。

默认目录地址为：

```text
https://raw.githubusercontent.com/jiuyi777/sillytavern-theme-assets/main/assets/%E5%9C%A8%E7%BA%BF%E4%B8%BB%E9%A2%98%E5%BA%93/catalog.json
```

目录会保留全部上传版本；主题卡片的默认区域只展示用户明确批准的正式版，测试版不会因为更新时间更新就自动公开。
目录通过无需登录、没有 GitHub API 匿名配额的 Raw 地址读取 `main` 最新版本；Raw 请求失败时自动尝试 jsDelivr。主题器按主题ID、版本号和下载地址判断已安装版本；旧版保存的 GitHub Contents API 地址会自动迁移到 Raw。

## 常用操作

- 第一次使用：打开“扩展 → 酒疫主题器”，点击“检查更新”。
- 需要防呆保护：在订阅器设置中勾选“在魔棒中显示返回入口”，之后可从输入区魔棒菜单点击 `✦ 返回上个主题`。
- 首次安装：点击“安装并切换”，插件校验并保存主题后自动刷新和启用。
- 已安装主题：点击“切换”即可直接启用；即使它只有测试版，切换走以后也不会从可见列表消失。
- 远程主题有新正式版：正式版本下拉默认选中推荐版本，按钮会显示“安装此版本并切换”。
- 使用测试版或历史版本：展开“其他版本”或“测试主题”，选择后点击“安装此版本并切换”。
- 更换主题库：在“主题目录地址”中填写另一个受信任的 GitHub、GitHub Pages 或 jsDelivr HTTPS 目录。
- 导入本地文件：选择 JSON 只会保存进主题器的本地收藏区；之后点“加入酒馆主题列表（不启用）”才写入酒馆，当前主题仍保持不变。
- 快速预览：点击主题卡上的眼睛按钮，通过按钮、键盘方向键或左右滑动连续查看当前日间／夜间分组中公开及已安装的主题；未安装的隐藏测试主题不会被“下一项”自动带出。

## 更新插件

- 通过 GitHub 仓库地址安装：在 SillyTavern 第三方扩展管理中执行更新。
- 手动安装：下载仓库最新版并覆盖 `theme-subscriber` 文件夹，然后刷新 SillyTavern。

## 常见问题

- 看不到插件：确认目录内直接存在 `manifest.json`，不要多套一层文件夹，然后刷新酒馆。
- 检查更新失败：确认设备能够访问 `raw.githubusercontent.com` 或 `cdn.jsdelivr.net`，稍后重试；插件不会因此修改现有主题。
- 拉取失败：检查主题地址是否可访问、返回内容是否为可解析JSON，以及目录主题名称是否与文件内部名称一致。
- 安装完成但没有切换：刷新一次酒馆，再从原生主题列表选择目标主题。
- 某个主题让页面按钮点不动：如果此前已开启保护，点击魔棒里的 `✦ 返回上个主题`；电脑上魔棒也无法展开时按 `Ctrl+Alt+Shift+R`。返回后到订阅器设置点击“删除刚才的坏主题”并确认。
- 救援边界：如果第三方代码导致整个页面 JavaScript 没有运行、酒馆服务器没有响应，扩展内按钮和快捷键都无法工作；这种情况需要重启酒馆后再使用救援入口，不能把扩展内按钮描述成操作系统级保证。
- 同名主题：SillyTavern 按主题内部 `name` 保存；在线目录把同一内部名称的文件归到一个主题卡片，并保留为多个可选版本。

## 隐私与安全

- 插件不读取聊天、API 密钥、Cookie 或私人设置内容。
- 只向当前 SillyTavern 的原生主题保存接口写入用户点击安装的主题。
- 本地选择的 JSON 先保存在浏览器 IndexedDB 中；不会上传到远程主题库或反馈服务。
- 不静默安装主题；用户点击主题按钮才会发生写入和切换。
- 主题远程字体、图片和 `@import` 会随主题 CSS 加载。

## 目录格式

参考 `catalog.example.json`。正式目录使用 schema v3，每个主题都必须提供：

- 稳定且唯一的 `id`
- 与主题 JSON 内 `name` 完全一致的 `name`
- `appearance`：`light` 或 `dark`
- 推荐提供 `logo_url`、`logo_alt`、`logo_palette`、`logo_subject` 和 `logo_effect`；Logo 必须来自当前主题真实设计证据，不得使用随机色卡
- `latest_version` 与只允许指向已批准版本的 `default_version`；没有正式版时后者为空字符串
- `versions` 数组；每个版本包含 `version`、`version_name`、`changelog`、`theme_url`、`status` 和 `approved`。旧目录中的 `sha256` 可以继续存在，但客户端会忽略它

测试版采用 `test-0.1`、`test-0.2` 递增，正式版采用 `0.1`、`0.2` 递增。上传不代表批准；只有用户明确说当前版本可以或完成，才写入 `approved: true` 并更新 `default_version`。订阅器仍兼容 schema v1/v2：旧目录的 `status: complete` 视为已批准，`status: test` 视为未批准。

## 维护者同步

`scripts/build-online-catalog.mjs --source <当前JSON>` 每次只处理当前一个主题版本，不扫描其他主题。`C:\aaaa` 来源写为隐藏测试版，`C:\1234` 来源写为用户已批准正式版；旧版本、固定提交链接和身份 Logo 全部继续保留。历史目录中的SHA-256仅作为旧元数据，不参与客户端下载或安装门禁。
